Hermes Agent memory provider · MIT

zvec-memory
local-first recall for Hermes

A memory provider that gives Hermes Agent long-term recall over a Markdown vault — hybrid keyword + semantic search, no cloud, no account, nothing leaves the machine.

near-vocabulary recall 10/10 prefetch p50 ~0.25 s warmed cache ~265× faster stdlib + zg only

01What it does

Hermes ships with small built-in memory (MEMORY.md / USER.md, a few thousand characters). zvec-memory adds the deep layer beside it: every turn it recalls relevant facts and session notes; every turn it files the conversation away. Two tools, one vault:

memory_search

Hybrid, fts-only, or vector-only retrieval over facts, decisions and session logs. Returns compact path:line citations with short previews, capped at 2000 chars of injected context.

memory_store

Append a durable fact — preference, decision, convention, fix. Reindexing happens in the background; the tool returns immediately.

02How it works

each turn: user msg ──▶ queue_prefetch warms cache (background) ──▶ prefetch reads cache (dict lookup, ~0 ms) └── cold fallback: zg query --preview short --limit 5 (~0.27 s) each turn: sync_turn appends sessions/YYYY-MM-DD.md (background) └── debounced zg index (serialized, never per-turn) session end: pattern extraction → facts/ (compaction handoffs excluded) built-in memory writes mirrored → facts/ engine: zvec-grep — BM25 + vector with RRF fusion, managed ripgrep

Recall runs through the zg CLI against a per-profile vault ($HERMES_HOME/zvec-memory/: facts/ + sessions/, index in .zvec-grep/). The shared zg server daemon keeps models loaded and refreshes in the background when running; --mode auto uses it when present and runs in-process otherwise.

03Measured value

From scripts/measure_recall.py — 20 seeded facts, 10 queries per set, reproducible on any machine with zg installed:

query sethybrid hit@5fts hit@5p50
same-vocabulary (the realistic case)10/1010/100.25 s
paraphrased, no shared keywords (adversarial)6/104/100.28 s

All 10 realistic hits were visible under the 2000-char injection cap. The warmed prefetch cache serves in ~0.000 s vs ~0.27 s cold. And the bigger embeddinggemma-300m model scored the same 6/10 on paraphrases while taking 125 s to build vs 3 s — so the tiny potion-retrieval-32m stays the default. Honest limits, shipped with the repo.

04Install

npm install -g @zvec/zvec-grep   # needs Node.js 22+
cp -r zvec-memory "${HERMES_HOME:-~/.hermes}/plugins/zvec-memory"
hermes memory status               # zvec-memory appears as local
hermes memory setup                # activate (one provider at a time)
zg server on                       # optional: shared models, background refresh

Configure via plugins.zvec-memory in config.yaml (vault, embedding, recall_limit, context_chars, auto_extract) or the desktop config panel. Remote embeddings stay opt-in behind an explicit zg auth grant — never automatic.
