01The problem it solves

Every chat with an AI starts from zero. Your preferences, past decisions, project conventions, hard-won environment fixes — all gone next session.

Without it

You re-explain your setup, re-state decisions, and watch the agent re-derive things it already solved last week. Built-in memory holds a few thousand characters — a sticky note, not an archive.

With zvec-memory

Every turn, relevant facts surface automatically. Every turn, the conversation is filed away. Ask about a decision from last month and the answer comes back with a citation to the exact note.

02What zvec and zvec-grep are

zvec-memory is the Hermes plugin. Its engine is zvec-grep (zg), an open-source search tool by zvec. Here is why that pairing matters, in plain terms.

Think of a great research librarian with two skills. First, a perfect index of every word in every book (keyword search). Second, an understanding of what you mean, even when you use different words (semantic search). zvec-grep does both at once over your notes, then fuses the two rankings so the best answer from either route wins.
🔎

Keyword search (BM25)

The classic book-index approach: exact terms, ranked by rarity and frequency. Unbeatable when you remember the exact words — error codes, names, commands.

🧠

Meaning search (vectors)

Your notes are converted to numeric fingerprints by a small embedding model that runs on your machine. Queries match by meaning, so "deployment broke" finds "the release failed" with zero shared words.

🔗

Smart fusion (RRF)

A fusion algorithm merges both rankings. Keyword precision plus semantic reach, with neither able to drown out the other. That is the hybrid in hybrid search.

🔒

Private by architecture

Index, models, and notes all live on your disk. There is no server to leak from and no subscription. Remote AI models stay strictly opt-in behind an explicit grant.

⚡

Fast enough to be invisible

Typical recall takes ~0.25 s, and a warmed cache answers in ~0 ms — recall happens before the model even starts thinking, so memory never slows a reply.

📊

Measured, not promised

Recall quality ships with numbers from a reproducible script in the repo — including the adversarial cases where it misses. See section 05.

03What it does inside Hermes

Two tools, one vault, three background habits. The agent does the remembering; you just talk.

memory_search

Ask anything about the past — preferences, decisions, projects. Hybrid, keyword-only, or meaning-only modes with path scoping. Answers come back as compact path:line citations, capped at 2000 chars of context.

memory_store

Tell it to remember something durable and it files a timestamped note instantly. Reindexing happens in the background; the tool returns immediately.

  1. Before each reply — relevant notes are recalled and injected as context.
  2. After each turn — the exchange is appended to today's session log.
  3. At session end — stated preferences and decisions are extracted as facts (opt-in).

04How it works

each turn: user msg ──▶ queue_prefetch warms cache (background) ──▶ prefetch reads cache (dict lookup, ~0 ms) └── cold fallback: zg query --preview short --limit 5 (~0.27 s) each turn: sync_turn appends sessions/YYYY-MM-DD.md (background) └── debounced zg index (serialized, never per-turn) session end: pattern extraction → facts/ (compaction handoffs excluded) built-in memory writes mirrored → facts/ engine: zvec-grep — BM25 + vector with RRF fusion, managed ripgrep

Recall runs through the zg CLI against a per-profile vault ($HERMES_HOME/zvec-memory/: facts/ + sessions/, index in .zvec-grep/). The shared zg server daemon keeps models loaded and refreshes in the background when running; --mode auto uses it when present and runs in-process otherwise.

05Measured value

From scripts/measure_recall.py in the repo — 20 seeded facts, 10 queries per set, reproducible on any machine with zg installed.

query sethybrid hit@5fts hit@5p50
same-vocabulary (the realistic case)10/1010/100.25 s
paraphrased, no shared keywords (adversarial)6/104/100.28 s

All 10 realistic hits were visible under the 2000-char injection cap. The warmed prefetch cache serves in ~0.000 s vs ~0.27 s cold. And the bigger embeddinggemma-300m model scored the same 6/10 on paraphrases while taking 125 s to build vs 3 s — so the tiny potion-retrieval-32m stays the default. Honest limits, shipped with the repo.

06Install

git clone https://github.com/r0b0tlab/hermes-zvec-memory
npm install -g @zvec/zvec-grep   # needs Node.js 22+
cp -r hermes-zvec-memory/zvec-memory "${HERMES_HOME:-~/.hermes}/plugins/zvec-memory"
hermes memory status               # zvec-memory appears as local
hermes memory setup zvec-memory    # activate (one provider at a time)
zg server on                       # optional: shared models, background refresh

Configure via the setup wizard or the desktop config panel (vault, embedding, recall limit, context cap, auto-extract). Remote embeddings stay opt-in behind an explicit zg auth grant — never automatic.
